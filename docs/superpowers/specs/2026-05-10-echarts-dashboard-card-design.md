# ECharts Dashboard Card Design

## Goal

Add a data dashboard card to Canvas Workbench that renders ECharts option JSON generated by external AI agents, scripts, or users through the CLI. The card should look like a minimal framed photo/dashboard panel rather than a heavy application widget.

## User Problem

Users want AI-generated data visualizations to appear directly on the Canvas Workbench canvas. The AI generation step should happen outside Canvas Workbench through tools such as Claude Code, Gemini CLI, or custom scripts. Canvas Workbench should receive the generated chart configuration through the Local API/CLI, save it as a card, and render it automatically in Web and Obsidian.

## Product Behavior

### Dashboard Card

Add a new card kind:

```ts
kind: 'dashboard'
```

A dashboard card displays:

1. A compact title/header.
2. A framed chart viewport rendered by ECharts.
3. Optional footer metadata such as generation source and update time.
4. A graceful empty/error state when the option is missing or invalid.

The visual style is **minimal framed dashboard**:

```text
┌──────────────────────────────┐
│ 销售数据看板              ⚙ │
├──────────────────────────────┤
│                              │
│          ECharts 图表区域     │
│                              │
├──────────────────────────────┤
│ claude-code · 刚刚更新        │
└──────────────────────────────┘
```

Style direction:

- Thin border and subtle inset frame.
- Low decoration, focused on the chart.
- Works on the existing dark canvas.
- Keeps current card drag/resize behavior.
- Resizing the card resizes the chart.

### CLI-Driven Creation

Canvas Workbench does not call an AI API in this version. External AI tools generate the ECharts option JSON and write it through the CLI.

Support both file and stdin input:

```bash
canvas-workbench dashboard add "销售看板" --option ./sales-option.json --grid "AI区"
```

```bash
cat sales-option.json | canvas-workbench dashboard add "销售看板" --stdin --grid "AI区"
```

Optional metadata arguments:

```bash
--data ./source-data.json
--prompt "生成销售趋势图"
--generated-by claude-code
```

First version requirements:

- `--option <path>` reads ECharts option JSON from a file.
- `--stdin` reads ECharts option JSON from standard input.
- Exactly one of `--option` or `--stdin` must be supplied.
- `--data <path>` optionally stores source data JSON or text.
- `--prompt <text>` optionally stores the prompt/instruction used by the external AI.
- `--generated-by <name>` optionally stores the generating tool name.
- `--grid <grid-name-or-id>` follows existing CLI grid behavior.

### Data Model

Extend `CardData` with dashboard state:

```ts
export type DashboardState = {
  option: unknown
  sourceData?: unknown
  prompt?: string
  generatedBy?: string
  updatedAt?: string
}
```

Add to `CardData`:

```ts
dashboard?: DashboardState
```

Add to `CardKind`:

```ts
'dashboard'
```

Default dashboard card size:

```ts
dashboard: { width: 760, height: 480 }
```

### Rendering

Use ECharts in the frontend:

```ts
import * as echarts from 'echarts'
```

Dashboard card rendering behavior:

1. Create a chart instance with `echarts.init(container)`.
2. Call `chart.setOption(sanitizedOption)`.
3. Observe card/container resize and call `chart.resize()`.
4. Dispose the chart on unmount.
5. Re-apply option when the dashboard option changes.

### Safety and Validation

Do not execute AI-generated JavaScript.

Rules:

- Accept JSON-compatible option objects only.
- Reject functions and executable code.
- Do not use `eval`.
- Do not inject arbitrary HTML through `innerHTML`.
- Limit option payload size in CLI/API validation.
- Show a readable error state instead of crashing when ECharts rejects an option.

A first version validator should check:

- The parsed value is a plain object.
- The object is JSON-compatible.
- No function-like string wrappers are executed.
- `series`, when present, is an array.
- The serialized option is below a conservative size limit.

### Empty and Error States

When no option exists:

```text
等待图表配置
请通过 CLI 写入 ECharts option
```

When option is invalid:

```text
图表配置无效
请检查 option JSON
```

When rendering fails:

```text
图表渲染失败
<short error message>
```

### Navigator and Labels

The card navigator should recognize dashboard cards.

Localized type label:

```text
数据看板
```

Label fallback stays the same:

1. card title
2. file name when relevant
3. localized card kind label

Dashboard metadata should prefer:

1. `generatedBy` when present
2. `updatedAt` when present
3. empty string

### Local API and Sync

The feature uses the existing Local API card creation/update flow. CLI-created dashboard cards should trigger the same `workspace.updated` path as other CLI-created cards, so Web and Obsidian auto-refresh after creation.

No cloud or external AI API is required for this version.

## Architecture

### Files to Change

- `src/shared/workspaceTypes.ts`
  - Add `dashboard` card kind.
  - Add `DashboardState` type.
  - Add dashboard default size.
  - Normalize dashboard state from persisted/external data.

- `src/cardChrome.ts`
  - Add dashboard chrome behavior.

- `src/cardNavigator.ts`
  - Add dashboard localized label and metadata.

- `src/App.tsx`
  - Add create action or rendering branch for dashboard cards.
  - Render a new dashboard card body.
  - Wire chart resizing and error states.

- `src/App.css`
  - Add minimal framed dashboard card styles.

- `src/dashboardOption.ts` or similar focused helper
  - Validate/sanitize dashboard options.
  - Provide safe error messages.

- `src/DashboardCard.tsx` or similar focused component
  - Own ECharts lifecycle.
  - Keep chart logic out of the large `App.tsx` body where possible.

- `bin/canvas-workbench.mjs`
  - Add `dashboard add` command.
  - Read `--option` file or `--stdin`.
  - Read optional `--data`, `--prompt`, and `--generated-by`.
  - Call Local API create card endpoint with `kind: 'dashboard'`.

- Tests
  - Add helper tests for dashboard option validation.
  - Add CLI source tests for `dashboard add`, `--option`, and `--stdin` support.
  - Extend navigator tests for dashboard labels/metadata.

### Dependency

Add ECharts as a frontend dependency:

```bash
npm install echarts
```

The bundle should be verified for both Web and Obsidian builds.

## Out of Scope for First Version

- Built-in AI API calls.
- API key configuration.
- Interactive chart editor.
- Export chart as image.
- Live external data source connectors.
- JavaScript formatter callbacks in ECharts options.
- Advanced map/geo assets.

## Testing

Automated tests should cover:

- `dashboard` is a recognized card kind.
- Dashboard default size is available.
- Dashboard option validator accepts valid JSON options.
- Dashboard option validator rejects non-object or structurally invalid options.
- Navigator label/type/metadata behavior for dashboard cards.
- CLI source includes dashboard command parsing for `--option` and `--stdin`.

Manual verification should cover:

1. Create dashboard from an option JSON file through CLI.
2. Create dashboard from stdin through CLI.
3. Obsidian auto-refresh shows the new dashboard card without manual import.
4. Chart renders inside the framed card.
5. Resizing the card resizes the chart.
6. Invalid option shows an error state without crashing.
7. Web build passes.
8. Obsidian build passes and copied plugin shows the card.
