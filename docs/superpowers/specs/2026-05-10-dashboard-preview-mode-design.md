# Dashboard Preview Mode Design

## Context

Canvas Workbench now supports ECharts dashboard cards generated by external AI/agents through the CLI and Local API. Dashboard cards currently render a live ECharts canvas in the card body so tooltip, legend, hover, and future chart interactions work immediately.

That always-live behavior makes the card feel different from other Canvas Workbench cards. When several cards sit together on the canvas, the dashboard chart can feel like it is competing with normal canvas organization gestures. The user wants dashboard cards to sit more naturally with other card types while still allowing full chart inspection when needed.

## Goal

Introduce a dashboard card interaction model with two modes:

1. **Preview mode** by default, where the dashboard behaves like a lightweight visual card and does not continuously claim chart interactions.
2. **Inspect mode** after an intentional click, where ECharts interactions are fully enabled.

The feature should preserve the existing visual direction: dashboard cards remain frameless/photo-like, use a top drag handle, and do not use the standard card header.

## Non-goals

- Do not add built-in AI calls or AI API key requirements.
- Do not change the dashboard card storage schema.
- Do not remove ECharts tooltip/legend/data interaction support.
- Do not make the whole dashboard card draggable, because the center area is reserved for chart viewing and inspection.
- Do not redesign unrelated card types.

## Interaction model

### Preview mode

Dashboard cards render in preview mode by default.

In preview mode:

- The top internal handle remains the only card-drag surface.
- The chart body shows the rendered ECharts visualization as a preview.
- The chart body presents an affordance such as `点击查看 / 交互`.
- Pointer-heavy ECharts interactions are not active by default.
- The card should feel close to image cards and ordinary canvas cards during layout work.
- Background canvas drag should not be visually or behaviorally disrupted by dashboard chart internals.

### Entering inspect mode

A user enters inspect mode by clicking the chart body / preview area.

In inspect mode:

- ECharts pointer interactions are enabled.
- Tooltip hover works.
- Legend clicks work.
- Future ECharts interactions such as dataZoom, brush, and selection can work.
- The card shows a clear inspect state, such as `查看中` and an `退出查看` control.
- The top internal handle still moves the card.

### Exiting inspect mode

A user can leave inspect mode through:

- Clicking `退出查看`.
- Pressing `Escape`.
- Clicking blank canvas background.

After exiting, the dashboard returns to preview mode and the chart no longer continuously participates in pointer-heavy interactions.

## Pointer boundaries

The intended pointer ownership is:

```text
Top dashboard handle        -> drag dashboard card
Dashboard preview body      -> click to enter inspect mode
Dashboard inspect chart     -> ECharts interactions
Blank canvas background     -> pan canvas
Resize handle               -> resize dashboard card
```

This keeps the dashboard card consistent with other card types during normal canvas organization, while still supporting deeper chart inspection on demand.

## Visual design

Preview mode should look like a chart preview card:

```text
┌──────────────────────────┐
│  销售趋势看板        ⋯⋯  │
│                          │
│        图表预览           │
│                          │
│      点击查看 / 交互       │
└──────────────────────────┘
```

Inspect mode should make the active state explicit:

```text
┌──────────────────────────┐
│  销售趋势看板      退出查看 │
│                          │
│        ECharts 交互区      │
│   tooltip / legend / hover │
└──────────────────────────┘
```

The visual treatment should stay subtle and compatible with the existing dark glass/photo-card aesthetic.

## Implementation notes

- `DashboardCard` should accept whether it is in inspect mode and callbacks to enter/exit inspect mode.
- `App` should track the currently inspected dashboard card id, likely as local UI state.
- Only one dashboard card needs to be in inspect mode at a time.
- Clicking another dashboard preview should inspect that card and leave the previous one.
- Global `Escape` handling should clear the inspected dashboard id.
- Canvas blank-background pointer down should clear the inspected dashboard id before starting pan.
- The chart container CSS should distinguish preview vs inspect mode:
  - Preview mode: rendered preview is visible, but chart internals should not continuously own pointer-heavy interactions.
  - Inspect mode: chart pointer events are enabled for ECharts.
- Existing validation and render error states should continue to work.

## Testing requirements

Add source or behavior tests covering:

- Dashboard cards default to preview mode.
- Preview mode has a click affordance for entering inspect mode.
- Inspect mode enables ECharts chart pointer interactions.
- Inspect mode exposes an exit control.
- `Escape` and blank-canvas pointer down clear inspected dashboard state.
- The top internal drag handle remains the only dashboard drag surface.
- Dashboard cards remain frameless and do not use the standard card header.

## Documentation requirements

Update relevant docs only if user-facing behavior is described there. The dashboard generation workflow docs do not need to change unless the CLI/AI card creation guidance mentions interaction behavior.

## Approval

Approved direction: use preview mode by default and require an intentional click to enable full chart inspection. This should make dashboard cards fit better alongside other Canvas Workbench cards while preserving ECharts interactions when the user asks for them.
